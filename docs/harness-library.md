# Harness library workspace

Open the Harness shelf with **E**, or press **F8**. The full-screen workspace is in Czech and in the office's own look (paper, ink borders, Nunito; `styles/base.css`). It has five pages and opens on Schránky:

- **Schránky** (boxes) lays the library out as twelve boxes around the model, after the Harness layout: AGENTS.md, Paměť, Skills, Správa kontextu, Subagenti and Crony a hooky on the agent's side, Nástroje in the middle, and Stavový automat, Evaluace, Smyčky, Měření a učení and Člověk ve smyčce for control and quality (`library/boxes-model.ts`). Each box takes its catalog categories and shows, apart, what the floor's effective profile **uses** (`effective` from `harness.hierarchy/1`; unknown on a legacy server, never guessed), what **waits in the library** (eight at a time, the rest under **Ukázat dalších**), and what the **office does itself**, each with its command or switch. A box with nothing yet says so (Subagenti), and a known gap is stated, not faked (memory does not feed recommendations). **Prohlédnout** shows a resource's real text, when an agent usually uses it, whether the floor uses it, where it lives and its version. The checkboxes fill the same package as the footer (**Vybráno N / 24**). **Doporučit balíček** fills it from `/api/harness/recommend` with each reason; **Složit a ověřit** builds it on the server through `/api/harness/kit` (every resource exists and is readable, pinned by SHA-256, at most 24 and 96 KiB) and adds the office's own checks: no rules, no testing, hooks that need a runner, resources outside the floor's profile, size. A change after verification marks it stale. **Co se bude dít** orders the package by phase (start of session, before work, during work, around events, before hand-in). The verified kit is copied or downloaded for the card's proposal (`fields.harness`); a person accepts it in Opora before a worker gets it. **Přiřadit do výbavy** switches the whole package on at the level open in Výbava (Projekt, or a page to card node of the bound Opora canvas) as an unsaved draft; **Uložit výbavu** makes every later preparation at that level get it. **Jak to udělá orchestrátor Opory** lists the same path as commands (`--search`, `--recommend`, `--kit`, `--configure LEVEL vrstva.json --task KEY`, `--accepted-kit`). The page keeps a reading width (1080 px) instead of stretching across a wide screen. Every action shows the matching `office-harness` command, so an agent can do the same.
- **Přehled** (overview) says in plain words what the library does. A status card for the floor shows the loaded resources, which hierarchy the server supports, whether the floor is bound to Opora, and whether this session may edit. Under it, four steps (Prostředky → Výbava → Příprava → Výsledky), the seven levels, the thirteen categories with their counts, the worker's commands for one card, and the sources found on disk. A successful `harness.hierarchy/1` response confirms the seven-level API and the session's write authority. A 404 identifies the legacy Global → Repository → Task server. Other errors stay errors, never an available capability.
- **Prostředky** (resources) keeps search, category and source filters, plain-text reading and copy/download of an ad-hoc pack (**Zkopírovat balíček**, **Stáhnout balíček**). These selections never change persistent configuration. **Přiřadit do výbavy** switches to Výbava with the resource added to the draft.
- **Výbava** (equipment) is the seven-level editor ([harness-hierarchy.md](harness-hierarchy.md)): pick a level, switch resources on or off, or restore inheritance (**Dědit**), then **Uložit výbavu**. Changing level is blocked while a draft is unsaved.
- **Pro agenty** lists the worker's `office-harness` commands in the order a card uses them (before, during and after the work), each with what it is for. They are references to implemented worker commands, **not browser actions or deployment detection**. The browser has no session API for their runtime state, and unknown production results stay unknown.

Category names are shown in Czech (`library/names.ts`); the catalog keeps its own IDs. Resource titles and texts come from the handbook and the repository and are shown as written.

The top-right **✕** and **Esc** use the office modal and focus lifecycle to resume mouse-look. On a phone the navigation becomes rows of tabs, the boxes stack in one column under the model, and the reader keeps its list/reader panes and keyboard shortcuts. Category counts describe the loaded catalog, including its truncation flag. A source found on disk does not establish a live OpenViking service, an MCP connection or Context7 credentials.

## Composition

`libraryWorkspace(el, () => floor, abort.signal, { boxes, hierarchy })` wraps the `.harness-cascade` editor that `hierarchyPanel` supplies. `ui.ts` constructs it after the dialog, calls `workspace.catalog(result)` after each successful catalog load (next to `cascade.catalog(result)`), and calls `workspace.show('equipment')` before assigning a resource. The floor getter follows project changes. `boxesPage(host)` (`library/boxes.ts`) gets the floor, the abort signal and the footer's package set from `ui.ts`, the catalog through `boxes.catalog(result)`, and the effective profile through the workspace's own hierarchy check, so the library makes no extra request for it.

The hierarchy API check confirms only server support. Closing the library by ✕ or Esc keeps an unsaved draft in memory (per floor, level, target and base revision), and the next opening returns to Výbava with a notice. A saved profile is planning data: it never mutates an accepted kit or a running execution.

## Verification

Run `npm run typecheck`, `npm test`, `npm run build`. With Vite running on port 5187, run `node tests/harness-boxes.browser.mjs` for the boxes (used vs library, office functions, Prohlédnout, the server kit verification, stale after a change, recommendation reasons, 1440/390 px) and `node tests/harness-workspace.browser.mjs` for desktop/mobile screenshots, real profile-switch payloads, read-only authority, optional hierarchy states, a Výbava draft kept across Esc/✕ and restored with a notice (then saved or discarded), category navigation, export and ✕/Esc. The test uses the actual catalog and reader with isolated route fixtures; it does not prove a production deployment or worker execution.
